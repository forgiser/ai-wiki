## 17.1 关键公式速查

### Self-Attention

```
Attention(Q, K, V) = softmax(QK^T / √d_k) × V

其中:
  Q = X × W_Q    [batch, seq, d_model] × [d_model, d_k]  → [batch, seq, d_k]
  K = X × W_K
  V = X × W_V
  d_k = d_model / num_heads

MultiHead(Q, K, V) = Concat(head_1, ..., head_h) × W_O
head_i = Attention(QW_Qi, KW_Ki, VW_Vi)

复杂度:
  时间: O(n²·d)  (n=序列长度, d=模型维度)
  空间: O(n²)    (存储attention矩阵)
```

### LoRA (Low-Rank Adaptation)

```
h = W_0·x + ΔW·x = W_0·x + B·A·x

其中:
  W_0: [d, k]  (冻结的原始权重)
  A: [r, k]    (低秩矩阵，随机初始化)
  B: [d, r]    (低秩矩阵，零初始化)
  r << min(d, k)

缩放因子: α/r  (α通常为r的2倍)
最终增量: ΔW = (α/r) · B·A

参数量对比:
  全参数更新: d × k
  LoRA更新: r × (d + k)
  压缩比: d·k / (r·(d+k))

例如 d=4096, k=4096, r=8:
  全参数: 16.8M, LoRA: 65.5K, 压缩256倍
```

### KV Cache 内存计算

```
KV Cache大小 = 2 × batch_size × num_layers × seq_len × num_heads × d_head × dtype_bytes

示例 (LLaMA-7B, FP16, seq_len=4096):
  = 2 × 1 × 32 × 4096 × 32 × 128 × 2
  = 2 × 1 × 32 × 4096 × 4096
  = 1,073,741,824 bytes ≈ 1 GB

示例 (LLaMA-70B, FP16, seq_len=4096):
  d_model=8192, num_heads=64, d_head=128
  = 2 × 1 × 80 × 4096 × 64 × 128 × 2
  = 2 × 1 × 80 × 4096 × 8192
  ≈ 10.7 GB
```

### RRF (Reciprocal Rank Fusion)

```
RRF_score(d) = Σ_i  1 / (k + rank_i(d))

其中:
  k = 60  (经典常数，用于平滑)
  rank_i(d) = 文档d在第i路检索中的排名(从1开始)

示例:
  文档A在BM25中排名1，在向量检索中排名3:
  RRF(A) = 1/(60+1) + 1/(60+3) = 0.01639 + 0.01587 = 0.03226

  文档B在BM25中排名2，在向量检索中排名2:
  RRF(B) = 1/(60+2) + 1/(60+2) = 0.01613 + 0.01613 = 0.03225

  文档A略胜出(但差距很小)
```

### DPO损失函数

```
L_DPO(π_θ; π_ref) = -E_{(x,y_w,y_l)~D} [log σ(β · Δ)]

其中重构的分对数差异:
  Δ = log(π_θ(y_w|x) / π_ref(y_w|x)) - log(π_θ(y_l|x) / π_ref(y_l|x))

  π_θ: 当前策略(训练的模型)
  π_ref: 参考策略(SFT后的冻结模型)
  β: 温度参数(通常0.1-0.5)，控制偏离π_ref的程度
  y_w: 偏好更好的回答(chosen/winning)
  y_l: 偏好更差的回答(rejected/losing)
  σ: sigmoid函数

直觉:
  - 模型应该增加chosen回答的相对概率
  - 模型应该减少rejected回答的相对概率
  - β越大，模型越不偏离参考策略
  - 损失下降 → chosen的log ratio增大，rejected的减小
```

### GRPO优势函数

```
对于每个prompt x，采样G个response {y_1, y_2, ..., y_G}:

  r_i = reward_model(x, y_i)
  A_i = (r_i - mean(r_1...r_G)) / std(r_1...r_G)

策略梯度:
  ∇_θ J = E [ (∇_θ log π_θ(y_i|x)) · A_i ]

优势:
  - 用组内相对排名替代绝对奖励，减少奖励模型的标度偏差
  - 不需要Value Network (Critic)，节省一半训练参数
  - 组内归一化天然做baseline subtraction

GRPO损失函数 (简化的clip版本):
  L_GRPO = -E [ min( ratio·A, clip(ratio, 1-ε, 1+ε)·A ) ]

其中 ratio = π_θ(y|x) / π_old(y|x)
```

### Transformer FLOPs估算

```
前向传播 (单层):
  Attention:
    QKV投影:    3 × batch × seq × d_model × d_model
    Attention计算: 2 × batch × seq² × d_model  (QK^T + ×V)
    Output投影:  batch × seq × d_model × d_model
    Attention合计: batch × seq × d_model × (4d_model + 2·seq)

  FFN (intermediate_dim = 4 × d_model):
    两个全连接层: 2 × batch × seq × d_model × 4d_model
    FFN合计: batch × seq × 8d_model²

  单层合计: batch × seq × (12d_model² + 2·seq·d_model)
            ≈ batch × seq × 12d_model²  (当d_model >> seq时)

  全模型(含embedding): num_layers × 单层 + 2 × batch × seq × d_model × vocab_size
  训练(含反向传播): ≈ 3 × 前向FLOPs

参数量估算:
  Attn: 4 × d_model²  (Q, K, V, O)
  FFN: 8 × d_model²   (up, gate, down for SwiGLU; 或2个大矩阵)
  单层参数: 12d_model²
  Embedding: vocab_size × d_model
  Total: num_layers × 12d_model² + vocab_size × d_model

  LLaMA-7B: 32 × 12 × 4096² + 32000 × 4096 ≈ 6.74B (不含lm_head共享)
  LLaMA-70B: 80 × 12 × 8192² + 32000 × 8192 ≈ 64.7B
```

### Attention 公式变体

```
标准 Self-Attention:
  Attn(Q,K,V) = softmax(QK^T / √d_k) · V

MQA (Multi-Query Attention):
  所有head共享K和V，只有Q每个head独立
  Attn(Q_h, K_shared, V_shared) = softmax(Q_h·K_shared^T / √d_k) · V_shared
  减少KV Cache: num_heads倍

GQA (Grouped-Query Attention):
  K和V分组共享（如8组），每组有独立的K和V
  平衡了MQA的效率损失和MHA的显存开销
  LLaMA-2 70B使用8组GQA

MLA (Multi-head Latent Attention, DeepSeek):
  将KV压缩到低维潜在空间(latent_dim << d_model)
  K = W_DK · c_KV, V = W_DV · c_KV
  其中c_KV是低维潜在表示
  减少KV Cache的同时保持表达能力
```

### 其他关键公式

```
RoPE (Rotary Position Embedding):
  f{q,k}(x_m, m) = R_{Θ,m}^d · W_{q,k} · x_m

  其中R_{Θ,m}^d是旋转矩阵:
  R_{Θ,m}^d = [[cos mθ_0, -sin mθ_0, 0, 0, ...],
              [sin mθ_0,  cos mθ_0, 0, 0, ...],
              [0, 0, cos mθ_1, -sin mθ_1, ...],
              ...]
  θ_i = 10000^{-2i/d}

RMSNorm:
  RMSNorm(x) = γ · x / sqrt(mean(x²) + ε)

  其中: mean(x²) = (1/d) Σ x_i²

LayerNorm:
  LayerNorm(x) = γ · (x - μ) / σ + β
  μ = mean(x), σ = std(x)

PPO Clip Objective:
  L_CLIP = E[min(r_t(θ)·A_t, clip(r_t(θ), 1-ε, 1+ε)·A_t)]
  r_t(θ) = π_θ(a_t|s_t) / π_old(a_t|s_t)
  通常 ε = 0.1 或 0.2

KL Divergence (用于RLHF中的约束):
  D_KL(π_θ || π_ref) = Σ π_θ(y) · log(π_θ(y) / π_ref(y))

Retrieval Metrics:
  Recall@K = |{相关文档} ∩ {检索Top-K}| / |{相关文档}|
  Precision@K = |{相关文档} ∩ {检索Top-K}| / K
  MRR = (1/N) Σ 1/rank_i
  NDCG@K = DCG@K / IDCG@K, 其中 DCG@K = Σ rel_i / log₂(i+1)
```

│  ┌───────────────────────────────────────────────────────┐   │
│  │ System: You are an AI assistant with access to tools.  │   │
│  │ Use the following format:                              │   │
│  │                                                        │   │
│  │ Thought: <your reasoning about what to do>             │   │

### 17.3.2 Plan-Execute模式

```
┌──────────────────────────────────────────────────────────────┐
│                   Plan-Execute Pattern                        │
│                                                               │
│  Phase 1: PLAN                                                │
│  ┌──────────────────────────────────────────────────────┐    │
│  │ Task → Planner → [Step1, Step2, Step3, ...]          │    │
│  │                                                       │    │
│  │ Example: "帮我安排明天的日程"                          │    │
│  │ Plan:                                                 │    │
│  │   Step1: 查询明天的天气                                │    │
│  │   Step2: 查询明天的日历事件                            │    │
│  │   Step3: 基于天气和日历给出建议                        │    │
│  └──────────────────────────────────────────────────────┘    │
│                           │                                    │
│                           ▼                                    │
│  Phase 2: EXECUTE                                             │
│  ┌──────────────────────────────────────────────────────┐    │
│  │  for each step in Plan:                               │    │
│  │    ├── Execute step (call tool / LLM)                 │    │
│  │    ├── Collect result                                 │    │
│  │    └── if failed → REPLAN or ADJUST                   │    │
│  └──────────────────────────────────────────────────────┘    │
│                           │                                    │
│                           ▼                                    │
│  Phase 3: AGGREGATE                                           │
│  ┌──────────────────────────────────────────────────────┐    │
│  │  Combine all step results → Final Answer              │    │
│  └──────────────────────────────────────────────────────┘    │
│                                                               │
│  关键设计决策:                                                │
│  - Plan的粒度: 太细→overhead大, 太粗→执行可能偏离            │
│  - Plan的修正: 执行中发现plan不对时如何处理                    │
│  - 依赖关系: 步骤间有依赖时如何调度                            │
└──────────────────────────────────────────────────────────────┘
```

### 17.3.3 Reflexion模式

```
┌──────────────────────────────────────────────────────────────┐
│                     Reflexion Pattern                         │
│                                                               │
│  ┌─────────┐     ┌─────────┐     ┌─────────┐                │
│  │  ACTOR  │────▶│ EVALU-  │────▶│  SELF-  │                │
│  │ (执行)  │     │  ATOR   │     │REFLECT  │                │
│  │         │     │ (评估)  │     │ (反思)  │                │
│  └─────────┘     └─────────┘     └────┬────┘                │
│       ▲                                │                      │
│       │          ┌──────────┐          │                      │
│       │          │  MEMORY  │◄─────────┘                      │
│       │          │(经验存储)│                                  │
│       │          └────┬─────┘                                  │
│       │               │                                        │
│       └───────────────┘                                        │
│         读取经验指导下次执行                                     │
│                                                                │
│  Algorithm:                                                    │
│  1. Actor生成trajectory: (a₁,o₁), (a₂,o₂), ..., (aₙ,oₙ)       │
│  2. Evaluator评估结果: success/fail + 评分                      │
│  3. Self-Reflection生成反思文本(如果失败):                       │
│     "我在步骤3时应该先检查API参数格式，而不是直接调用"            │
│  4. 反思存储到Memory                                           │
│  5. 下次执行时读取相关反思作为额外上下文                          │
│                                                                │
│  关键设计:                                                      │
│  - 反思的质量决定改进效果                                        │
│  - 反思的检索：需要找到与当前任务相关的反思                       │
│  - 过多反思→context污染, 可以设置反思的时效性                     │
└──────────────────────────────────────────────────────────────┘
```

### 17.3.4 LATS (Language Agent Tree Search)

```
┌──────────────────────────────────────────────────────────────┐
│                        LATS                                   │
│                                                               │
│                    ┌─────────┐                                │
│                    │  START  │                                │
│                    └────┬────┘                                │
│                    ┌────┼────┐ (生成N个候选Action)             │
│                    │    │    │                                │
│               ┌────▼┐ ┌▼──┐ ┌▼────┐                          │
│               │ Act1│ │Act2│ │Act3 │  ← 第一层                │
│               └──┬──┘ └─┬──┘ └──┬──┘                          │
│            ┌─────┼──┐   │  ┌────┼───┐                        │
│            │     │  │   │  │    │   │                         │
│          Act1.1  ...  Act2.1  Act3.1 ...   ← 第二层           │
│                                                               │
│  Monte Carlo Tree Search (MCTS) + LLM:                        │
│  1. Selection: 从根开始,用UCT选择最有潜力的路径                 │
│     UCT(s,a) = Q(s,a) + c·√(log N(s) / N(s,a))               │
│  2. Expansion: LLM生成新的候选Action,扩展树                    │
│  3. Simulation: 用LLM模拟执行到结束状态(rollout)                │
│  4. Backpropagation: 将结果沿着路径反向传播更新Q值               │
│  5. Reflection: 对失败路径做反思,生成可学习的经验                │
│                                                               │
│  优势: 结合了搜索的全局视野 + LLM的生成能力                      │
│  代价: 计算开销大(每步需要多次LLM调用)                          │
└──────────────────────────────────────────────────────────────┘
```

### 17.7.1 Simple ReAct Agent Loop

```python
import re
import json
from typing import Dict, List, Any, Callable

class SimpleAgent:
    """简化的ReAct Agent实现"""

    def __init__(self, llm_call: Callable, tools: Dict[str, Callable],
                 max_steps: int = 10, max_timeout: float = 120.0):
        self.llm = llm_call
        self.tools = tools
        self.max_steps = max_steps
        self.max_timeout = max_timeout
        self.tool_schemas = self._build_tool_schemas()

    def _build_tool_schemas(self) -> str:
        schemas = []
        for name, func in self.tools.items():
            schemas.append({
                "name": name,
                "description": func.__doc__ or "",
                "parameters": {"type": "object", "properties": {}}
            })
        return json.dumps(schemas, indent=2, ensure_ascii=False)

    def _build_prompt(self, query: str, history: List[Dict]) -> str:
        return f"""You are an AI assistant with access to tools.

Available tools:
{self.tool_schemas}

Use this format:
Thought: <your reasoning>
Action: <tool_name>(<json_params>)
Observation: <tool result>
... (repeat as needed)
Thought: I have the answer
Final Answer: <your response>

User: {query}
Assistant: """

    def _parse_action(self, text: str):
        """从LLM输出中解析Action"""
        pattern = r'Action:\s*(\w+)\((.*?)\)'
        match = re.search(pattern, text, re.DOTALL)
        if not match:
            return None, None
        tool_name = match.group(1)
        params_str = match.group(2)
        try:
            params = json.loads(params_str)
        except json.JSONDecodeError:
            params = {}
        return tool_name, params

    def run(self, query: str) -> str:
        import time
        start_time = time.time()
        history = []
        last_actions = []  # 用于检测重复动作

        for step in range(self.max_steps):
            # 超时检查
            if time.time() - start_time > self.max_timeout:
                return "任务超时，请在当前状态下给出最佳回答"

            # 调用LLM
            prompt = self._build_prompt(query, history)
            response = self.llm(prompt)

            # 检查是否是最终答案
            if "Final Answer:" in response:
                return response.split("Final Answer:")[-1].strip()

            # 解析Action
            tool_name, params = self._parse_action(response)
            if tool_name is None:
                history.append({"role": "assistant", "content": response})
                history.append({"role": "system", "content":
                    "请使用Action格式调用工具，或给出Final Answer"})
                continue

            # 检测重复动作
            action_key = f"{tool_name}:{json.dumps(params, sort_keys=True)}"
            last_actions.append(action_key)
            if len(last_actions) > 3 and len(set(last_actions[-3:])) == 1:
                history.append({"role": "system", "content":
                    "你已连续3次执行相同操作，请反思是否进入循环并调整策略"})
                continue

            # 执行工具
            if tool_name not in self.tools:
                obs = f"错误：工具 '{tool_name}' 不存在。可用工具：{list(self.tools.keys())}"
            else:
                try:
                    result = self.tools[tool_name](**params)
                    obs = str(result)
                except Exception as e:
                    obs = f"工具执行错误：{str(e)}。请修正参数后重试。"

            history.append({"role": "assistant", "content": response})
            history.append({"role": "system", "content": f"Observation: {obs}"})

        return "达到最大步骤限制，无法完成任务"
```

### 17.7.2 Model Router with Circuit Breaker

```python
import time
import random
from enum import Enum
from dataclasses import dataclass, field
from collections import defaultdict

class CircuitState(Enum):
    CLOSED = "closed"           # 正常运行
    OPEN = "open"              # 熔断中，拒绝请求
    HALF_OPEN = "half_open"    # 半开，试探性请求

@dataclass
class ModelEndpoint:
    name: str
    cost_per_token: float
    avg_latency: float  # ms
    circuit_state: CircuitState = CircuitState.CLOSED
    failure_count: int = 0
    last_failure_time: float = 0.0
    success_count: int = 0
    last_success_time: float = 0.0

class ModelRouter:
    """模型路由 + 熔断器"""

    def __init__(self, failure_threshold: int = 5,
                 recovery_timeout: float = 30.0,
                 half_open_max: int = 3):
        self.endpoints: Dict[str, ModelEndpoint] = {}
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.half_open_max = half_open_max
        self.latency_window: Dict[str, list] = defaultdict(list)

    def register(self, name: str, cost: float, latency: float):
        self.endpoints[name] = ModelEndpoint(
            name=name, cost_per_token=cost, avg_latency=latency
        )

    def route(self, complexity: str, query_tokens: int) -> str:
        """
        路由策略:
        - simple: 低成本小模型
        - normal: 平衡模型
        - complex: 最强模型
        """
        complexity_map = {
            "simple": ["gpt-3.5-turbo", "qwen-7b", "llama-3-8b"],
            "normal": ["gpt-4o", "qwen-72b", "llama-3-70b"],
            "complex": ["gpt-4", "claude-3.5-sonnet", "deepseek-v3"]
        }

        candidates = complexity_map.get(complexity, complexity_map["normal"])
        available = [c for c in candidates
                     if c in self.endpoints
                     and self.endpoints[c].circuit_state != CircuitState.OPEN]

        if not available:
            # 全部熔断，选最低成本的降级模型
            available = [e.name for e in self.endpoints.values()
                        if e.circuit_state != CircuitState.OPEN]
            if not available:
                return min(self.endpoints.keys(),
                          key=lambda x: self.endpoints[x].cost_per_token)

        # 加权随机选择(考虑延迟和成本)
        weights = []
        for name in available:
            ep = self.endpoints[name]
            score = 1.0 / (ep.avg_latency * ep.cost_per_token)
            weights.append(score)

        total = sum(weights)
        probs = [w / total for w in weights]
        return random.choices(available, weights=probs, k=1)[0]

    def report_success(self, endpoint_name: str, latency: float):
        ep = self.endpoints.get(endpoint_name)
        if not ep:
            return
        ep.failure_count = 0
        ep.success_count += 1
        ep.last_success_time = time.time()

        # 半开状态恢复
        if ep.circuit_state == CircuitState.HALF_OPEN:
            if ep.success_count >= self.half_open_max:
                ep.circuit_state = CircuitState.CLOSED
                ep.success_count = 0

        # 更新滑动窗口延迟
        self.latency_window[endpoint_name].append(latency)
        if len(self.latency_window[endpoint_name]) > 100:
            self.latency_window[endpoint_name].pop(0)
        ep.avg_latency = sum(self.latency_window[endpoint_name]) / \
                         len(self.latency_window[endpoint_name])

    def report_failure(self, endpoint_name: str):
        ep = self.endpoints.get(endpoint_name)
        if not ep:
            return
        ep.failure_count += 1
        ep.last_failure_time = time.time()

        if ep.circuit_state == CircuitState.HALF_OPEN:
            ep.circuit_state = CircuitState.OPEN  # 半开失败，重新熔断
        elif ep.failure_count >= self.failure_threshold:
            ep.circuit_state = CircuitState.OPEN  # 触发熔断

    def check_and_recover(self):
        """检查是否可以恢复"""
        now = time.time()
        for ep in self.endpoints.values():
            if ep.circuit_state == CircuitState.OPEN:
                if now - ep.last_failure_time > self.recovery_timeout:
                    ep.circuit_state = CircuitState.HALF_OPEN
                    ep.success_count = 0
```

## 17.8 常见错误与失败模式

### 17.8.1 Agent设计常见错误

| 错误 | 表现 | 根因 | 修复 |
|------|------|------|------|
| **无限循环** | Agent重复相同操作 | 无步数限制+无去重检测 | 见难3的解决方案 |
| **工具参数幻觉** | 传入不存在的函数名/参数 | LLM缺乏对工具的真正理解 | 更详细的Schema+few-shot示例 |
| **过早终止** | 任务未完成就宣布结束 | Prompt未强调"确认完成" | 增加验证步骤+Completion Check |
| **过度使用工具** | 简单问题也反复调用工具 | System Prompt未强调效率 | 加"不需要工具时直接回答"指令 |
| **上下文遗忘** | 对话后期忘记前期信息 | Context Window溢出 | 摘要压缩+长短期记忆分离 |
| **工具结果误读** | 将失败的返回当作成功 | 缺少返回格式的明确约定 | 统一返回格式{success,data,error} |
| **并发工具调用失败** | 同时调多个工具有依赖错误 | 未考虑工具间的依赖 | 显式声明依赖+顺序执行 |

### 17.8.2 RAG系统常见错误

| 错误 | 表现 | 根因 | 修复 |
|------|------|------|------|
| **检索不相关** | 返回与问题无关的文档 | Embedding匹配不足 | 多路检索+query改写+HyDE |
| **上下文窗口浪费** | 大量不相关chunk占满prompt | Chunk选择不精准 | 更好的reranker+Top-K调优 |
| **分块破坏语义** | 答案分散在多个chunk中 | 固定大小分块 | 语义分块+小chunk+parent retrieval |
| **幻觉+引文** | 编造引文来源 | 模型"强行"引用 | 强制标记是否有引文+后验证 |
| **时效性问题** | 返回过时信息 | 知识库未更新 | CDC(Change Data Capture)+定时重建索引 |
| **多跳问题失败** | 需要多步推理的检索失败 | 单次检索不够 | Iterative Retrieval+多跳RAG |
| **用户query表达差** | "那个东西" "上次说的那个" | 无query上下文 | 多轮+指代消解+query改写 |

### 17.8.3 Prompt设计常见错误

| 错误 | 表现 | 根因 | 修复 |
|------|------|------|------|
| **指令冲突** | 前后不一致的行为 | 多处指令矛盾 | 统一指令源+末尾重复核心约束 |
| **过长的System Prompt** | 模型忽略中间指令 | Lost in the Middle | 压缩+关键指令放开头和结尾 |
| **缺少输出格式约束** | 格式不统一 | 未指定格式 | JSON Schema+few-shot format示例 |
| **负面指令** | "不要说X"反效果 | 负面指令强化了X的激活 | 正面指令"请只回答Y" |
| **过度约束** | 模型过于保守 | 太多"不要" | 分级约束+场景化System Prompt |

### 17.8.4 生产环境失败模式

| 问题 | 影响 | 预防措施 |
|------|------|----------|
| **GPU OOM** | 服务crash | 内存预估+限流+predictive scaling |
| **模型API限流** | 请求排队/失败 | Rate limiter+队列+多provider |
| **向量库宕机** | RAG全部失败 | 多副本+降级到关键词检索 |
| **Token消耗暴涨** | 成本超预算 | 每日预算上限+异常告警 |
| **模型输出质量骤降** | 用户投诉 | 输出质量自动检测+自动回滚模型版本 |
| **数据库连接泄漏** | 雪崩式故障 | 连接池+超时+熔断 |
